# Декомпозиция и оценка трудоёмкости

## Как читать таблицу

- **O** — оптимистичная оценка.
- **M** — наиболее вероятная оценка.
- **P** — пессимистичная оценка.
- **E** — ожидаемая трудоёмкость: `E = (O + 4·M + P) / 6`.
- **Факт** — фактическое время.
- **Комментарий** — причина расхождения, если факт отличается от E более чем в 1,5 раза.

Задачи, общие для обеих страниц, оценивались один раз (в колонке «Страница» — «обе»).

## Выводы

**Что сработало:**

1. **План, составленный до кода**, сэкономил время: к моменту вёрстки структура была ясна, не пришлось переделывать.
2. **Словарь токенов** из Figma Inspect дал точные значения вместо «на глаз».
3. **Разделение на этапы** позволило видеть прогресс и вовремя замечать отклонения.
4. **Резерв 15 %** не понадобился — оценка оказалась даже слегка пессимистичной.

**Что недооценил:**

1. **Изучение макета** заняло вдвое больше времени: две страницы, много секций, нерегулярная сетка отступов.
2. **Словарь токенов** потребовал уточнений: первая версия по скриншотам оказалась неточной, пришлось получать CSS из Figma.
3. **Правки выравнивания** (коллаж, кнопка play, центрирование надзаголовков) — типичные доработки, которые редко попадают в план.

**Что добавил в собственный чек-лист:**

- проверять **обе страницы сразу**, а не только главную;
